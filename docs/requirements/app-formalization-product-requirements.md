# Robot App 正式化产品需求

状态：待实现与联合验收  
适用设备：手机真机、平板模拟器  
当前唯一联调设备：`crawler/crawler_00000001`

## 1. 文档定位

本文把甲方整机研制要求转换为 App 可实现、可测试的产品要求，不定义新接口，也不改变
V1–V6 原文。接口冲突按以下当前基线解释：

- 基础账号、设备和通用交互：V3 未被后续覆盖的部分；
- 自动任务、手动控制和任务最终状态：V4.3；
- 地图上传、激活、查询、缓存和位姿：V5 Map V2；
- GPS、温度、电流和姿态：V6。

Robot 是整机能力的实现主体。App 只展示 Robot 通过现有接口提供的真实结果，并通过现有
MQTT 接口提供自动和手动两种控制。当前没有实体遥控器控制链路。

## 2. 产品目标

正式版需要让普通用户无需理解 MQTT、ACK、Topic 或内部任务栈，也能完成以下闭环：

1. 登录并选择有权限的真实设备；
2. 明确判断当前设备、在线状态、安全状态和工作模式；
3. 查看地图、位置、航向、轨迹和设备遥测；
4. 安全执行自动任务、手动控制、停止和急停；
5. 查看作业、故障和 App 诊断记录；
6. 在网络失败、设备离线、命令拒绝和数据缺失时得到明确提示；
7. 通过固定签名的测试或稳定渠道完成 App 更新。

## 3. 当前约束与非目标

- 仅 `crawler_00000001` 进入当前联合验收，不能回退到默认设备或展示不存在的 `rk3588`；
- 手机必须真机验收；甲方未提供平板，平板当前只做模拟器兼容验收；
- 本阶段不新增 MQTT Topic、Payload 字段或 Cloud API；接口不足时形成差异项，由 Robot
  负责人发起文档变更；
- 带 `（*）` 的运维计划、路径智能导入、智能充电、故障诊断和扩展视觉能力不在本轮新增
  App 入口；
- App 不运行路径规划、视觉导航、惯视融合或 BMS 算法，只展示现有接口结果；
- Wi-Fi 配置和 Robot 固件升级只有在 Robot 执行链路闭环后才可显示为可用功能。

## 4. 信息架构

手机使用底部导航，平板使用左侧导航栏；页面名称和业务顺序保持一致：

```text
总览
地图
控制
记录
更多
```

### 4.1 全局设备栏

进入设备工作台后，所有一级页面必须持续展示：

- 设备名称和 `deviceId`；
- 在线/离线；
- 当前模式 `auto/manual`；
- 安全状态；
- 电量；
- 返回设备列表入口。

切换设备、退出登录或 Token 失效时，必须停止旧设备订阅和控制，清除旧会话实时状态。

### 4.2 手机布局

- 使用底部导航；
- 内容区域允许纵向滚动，不通过缩小字号强行容纳；
- 急停在总览和控制页保持清晰可见；
- 方向控制、速度选择和停止操作处于同一视觉区域。

### 4.3 平板布局

- `sw600dp` 及以上使用左侧导航栏和右侧内容区；
- 不直接拉伸手机底部导航；
- 地图与状态可以组成双栏，但不能缩小控制按钮；
- 当前只要求模拟器验证常用横屏分辨率；真实平板型号确定后补做真机验收。

## 5. 页面需求

### APP-F01 登录

- 支持账号和密码登录、显示/隐藏密码、加密记住登录信息；
- 登录中防止重复提交；
- 区分账号错误、网络失败、服务不可用和会话失效；
- 页面显示 App 版本；
- 有效会话可直接进入设备列表，退出登录后回到登录页。

### APP-F02 设备列表

- 只显示当前账号有权限且身份格式有效的 Robot 设备；
- 卡片显示设备名称、编号、在线状态、电量和最近状态摘要；
- 提供刷新、加载失败重试、空列表和搜索；
- 离线设备允许查看非实时信息，但不得进入可移动控制状态；
- 不得用默认身份替代接口返回的未知或非法设备。

### APP-F03 总览

- 展示在线、安全、模式、电量、速度、任务状态、任务进度和当前故障摘要；
- 展示地图缩略图及 Robot 当前位姿；
- 展示 GPS 状态、板面倾角估算和主要温度；
- 提供自动任务主要操作、普通停止和急停；
- 不放置 Wi-Fi、固件升级等低频维护入口。

没有协议值时显示 `--` 或“暂无数据”，不得显示假 `0`。技术错误需要转换为用户可理解的
结果，同时在诊断日志保留错误码。

### APP-F04 地图与轨迹

- 按 V5 通过 Bearer Token 查询当前地图、精确版本并下载内容；
- 展示地图名称、版本、同步状态、Robot 位置、航向和最近 10 秒轨迹；
- 支持缩放、显示全部和居中 Robot；
- 地图身份不匹配时立即隐藏位置并重新同步；
- 无地图、同步中、加载失败、使用验证缓存和身份不匹配需要有不同提示；
- GPS 地理坐标不得替代光伏板地图 `pose`。

### APP-F05 自动控制

- 支持 `start/stop/pause/resume/replan`；
- START 前校验在线、安全状态和有效地图；
- 命令需要展示“发送中、已受理、执行成功或失败”；
- `cmd_ack` 只代表受理，最终结果以 V4.3 `status` 为准；
- 根任务结果使用 `rootMissionId/orchestrationState`，不能把内部子任务完成显示为整项完成。

### APP-F06 手动控制

- 进入页面后发送 `manual`，同时等待 ACK 和 `status.operationalMode=manual`；
- 安全状态正常后才允许非零速度；
- 长按方向约 20 Hz 发送 `remote`，松手立即发送零速；
- 页面失焦、App 后台、MQTT 断开、状态异常或离开页面时发送零速；
- 退出手动控制后发送 `auto`；
- Robot 仍必须实现遥控超时零速，App 零速不能替代 Robot 安全保护。

### APP-F07 安全控制

- 急停保持一键立即发送，不增加会拖慢操作的确认；
- 解除急停必须二次确认，并等待 ACK 与安全状态恢复；
- 离线、故障、急停或非手动状态时禁用移动；
- 禁用按钮必须说明原因；
- 普通停止与急停在颜色、位置和文案上明确区分。

### APP-F08 状态和遥测

- 按 V6 展示 GPS、机身/H7/RK3588 温度、总电流、roll/pitch/yaw 和板面倾角估算；
- 空值和字段缺失显示 `--`，非法单字段不能丢弃整条状态；
- 电流保留正负号，不自行解释为充电或放电；
- 心跳超时后明确标记整组数据离线或陈旧；
- 不把一个设备的状态显示到另一个设备。

### APP-F09 记录

记录页分为：

1. 作业记录：Cloud `jobs` 返回的时间、结果和清扫信息；
2. 故障记录：App 在线期间从现有状态和错误字段记录的故障变化；
3. App 诊断日志：HTTP、MQTT、解析、控制和地图同步事件。

当前 V1–V6 没有定义完整的云端故障历史接口，因此不得把本地故障记录宣传为完整设备历史。
日志页面不得显示密码、Token 或 MQTT 凭据。

### APP-F10 更多与设备设置

包含作业入口、Wi-Fi、Robot 固件升级、App 更新、版本信息、本地日志和退出登录。

- Wi-Fi 修改与固件升级需要维护权限、二次确认和明确执行结果；
- Robot 链路没有闭环时显示“暂不可用”，不能显示假成功；
- 关于页面显示 `versionName`、`versionCode`、发布渠道和可识别的构建提交；
- App 更新继续校验文件大小、SHA-256、包名、版本号和签名证书。

## 6. 统一页面状态和文案

所有依赖网络或设备数据的页面都需要覆盖：

| 状态 | 用户表现 |
|---|---|
| Loading | 显示进度，避免重复提交 |
| Content | 展示当前真实数据和更新时间 |
| Empty | 解释为什么没有数据，并提供可行操作 |
| Error | 给出重试入口和用户可读原因 |
| Offline/Stale | 保留必要上下文，但明确数据非实时并禁用危险操作 |

用户文案不直接出现 Topic、JSON、HTTP 栈或内部异常。诊断详情可以保留稳定错误码和时间。

## 7. 验收方式

### 7.1 手机真机

必须覆盖登录、设备刷新、地图、自动任务、手动控制、松手零速、前后台切换、急停、断网、
重连、日志、App 更新、软键盘、滚动和触摸操作。控制类结果必须同时对照 App UI、MQTT
消息与 Robot 实际动作。

### 7.2 平板模拟器

至少覆盖常用横屏尺寸下的启动、导航、滚动、弹窗、地图、自动控制和手动控制，要求无重叠、
截断、不可点击或崩溃。验收记录必须注明“模拟器兼容通过，甲方平板真机未验收”。

### 7.3 工程门禁

每次代码变更至少通过：

```powershell
.\tools\run-gradle.ps1 testDebugUnitTest lintDebug assembleDebug
```

正式发布还需要固定签名 Release APK、版本信息、SHA-256、测试结果和联合验收报告。

## 8. 实施优先级

### P0：正式测试版前完成

- 五个一级页面和手机/平板自适应导航；
- 全局设备与安全状态；
- 设备刷新、失败重试和空状态；
- 作业、故障、诊断记录分层；
- 解除急停确认；
- Wi-Fi、固件和作业记录迁入“更多”；
- 关于/版本页；
- 统一 Loading/Content/Empty/Error/Offline；
- 手机真机回归和平板模拟器回归。

### P1：接口或设备条件具备后完成

- Robot Wi-Fi 执行闭环；
- Robot 固件升级进度与结果闭环；
- 甲方指定平板真机验收；
- 新的故障历史、运维计划、视频、路径导入或智能充电能力。

## 9. 变更规则

任何新增 Topic、字段、枚举、错误码或 HTTP API，必须先说明：负责方、兼容策略、空值规则、
安全影响、测试样例和回退方式。文档确认后再修改 Robot、Cloud 和 App，不能仅根据口头样例
在 App 中推测实现。
